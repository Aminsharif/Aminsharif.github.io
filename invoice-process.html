The n8n Workflow

A single n8n workflow with two paths: document ingestion & embedding, and a webhook-driven RAG Q&A. The pipeline was designed directly in n8n with a parent-child storage model backed by PostgreSQL.

Every uploaded file is extracted to text, summarized by the LLM, stored as a parent document, then split into sections and overlapping chunks — each chunk embedded and stored with a document_id foreign key.

RAG Q&A with Citations

Questions are embedded and matched against stored chunks using a combined score (40% BM25 + 60% vector similarity). Top 8 chunks become cited context, and the LLM answers strictly from that context with [Ref N] references.

AI / LLM Layer

Powered by OpenAI (gpt-4.1-nano for summarization and answering, text-embedding-3-small for embeddings) through n8n LangChain nodes and REST API calls.

Results

What This System Automates

  • Turns uploaded invoices and contracts into searchable, AI-accessible documents without manual data entry
  • Generates a concise LLM summary of every document at ingestion time
  • Splits long documents into structured, overlapping chunks that preserve context across sections
  • Stores vector embeddings alongside full text in PostgreSQL (pgvector) for fast semantic retrieval
  • Answers questions with hybrid BM25 + vector search and cites the exact document and section used
  • Exposes a REST webhook so any frontend can query the document knowledge base

No campaign metrics have been invented here — measurable numbers will be added once live usage produces them.
