Case Study

ContextMesh AI — Multi-Tenant RAG & LangGraph Platform

A multi-tenant RAG service with a LangGraph agent, hybrid pgvector + BM25 retrieval with reranking, an 8-stage idempotent ingestion pipeline, and enterprise-grade auth, auditing, and observability.

  • LangGraph
  • FastAPI
  • PostgreSQL + pgvector
  • Redis
  • Next.js

Explore the Architecture Build Something Similar

Problem & Solution

Problem

  • Naive RAG answers drift from the source documents
  • One retrieval strategy misses both keyword and semantic matches
  • No tenant isolation for multi-customer deployments
  • Re-ingesting unchanged documents wastes embeddings spend
  • No observability into retrieval quality or usage

Solution

  • LangGraph agent — router, multi-query, grading, safe fallback
  • Hybrid retrieval — pgvector + BM25 fused with RRF, then reranked
  • Tenant partitioning (16 hash buckets) with strict isolation
  • 8-stage idempotent ingestion — skips unchanged content
  • Per-tenant usage analytics, eval suites & release gates
  • Audit log, PII redaction & SOC2/GDPR-ready controls

Core Pipelines

This platform is built on LangGraph and FastAPI rather than n8n. The state graph, retrieval flow, and ingestion pipeline below are the exact flows implemented in code.

LangGraph Agent Graph

StateGraph
Context Layer tenant context
LLM Understanding → Dynamic Task Planner intent
Tool Registry → Execution Engine RAG / actions / compute
Rewrite Question → Generate Queries multi-query ×3
Retrieve — Hybrid pgvector + BM25
Rerank API / local BGE
Validation & Safety grade 0–10
Generate / Chat / Fallback → END citations

A conversational RAG state graph: route query vs chat, rewrite and expand the query, generate multiple search queries, retrieve, rerank, grade relevance, then answer with citations — or take a safe chat-only/fallback path.

Retrieval Pipeline

hybrid
Query Rewrite + Expansion optimizer
Vector Search (pgvector HNSW) tenant-scoped
BM25 Search (tsvector + body_text) parallel
Merge + Dedup (RRF) score-weighted
Rerank cross-encoder
Expand Children → Parents adjacency hop
Context Packing section stitch
LLM Generation + Citations → Audit retrieval_logs

Every query is rewritten and expanded, searched in parallel across vector and full-text indexes, fused with RRF, reranked, expanded back to parent sections, packed into context, and answered with enforced citations — all logged per tenant.

Ingestion Pipeline

8 stages
raw upload + job row
extracted PDF/HTML → markdown
chunked parent ≈2.5k + child ≈500
embedded CachingEmbeddings
bm25 tsvector / body_text
vectors child rows + pgvector
committed ACL snapshot
promoted revision activated

Each stage commits before advancing, is idempotent via completion fingerprints (retries skip completed work and preserve embedding spend), respects cancellation checkpoints, and routes failures to a dead-letter queue after max retries.

Auth & Security

enterprise
JWT Access — 30 min (HS256) signed
Refresh Tokens — 7 days revoke + device binding
Email Verification 24h · single-use

Rate Limits per-IP + per-email
Admin Audit Log SOC2 / GDPR-ready

JWT access + rotating refresh tokens with device binding, email verification, RBAC, per-IP rate limits, and an admin audit log that never blocks the underlying action — the table compliance reviewers read.

Every user query is traceable end-to-end through JSON log streams, retrieval is audited per tenant, metrics are Prometheus-exposed, and PII is redacted at the log layer.

Multi-Provider LLM Layer

pluggable
OpenAI chat + embeddings
Anthropic · Gemini · Groq · DeepSeek chat
Ollama (local) · HuggingFace self-hosted
Embeddings — OpenAI / Cohere HF local fallback
Reranker — Cohere / HF cross-encoder or pointwise scoring
Timeouts + Circuit Breakers every provider call

Providers are configured per tenant through admin-managed models. Every external call is timeout-bounded with circuit breakers, and the reranker falls back to a local BGE model when no API reranker is configured.

Results

What This System Automates

  • Multi-tenant RAG with strict isolation via 16-bucket hash partitioning of chunks and vectors
  • 8-stage ingestion where retries skip completed stages by fingerprint — preserving embedding spend
  • Hybrid retrieval that fuses vector similarity and BM25 full-text via RRF, then reranks candidates
  • A LangGraph agent that routes chat vs retrieval, generates multi-queries, grades relevance, and falls back safely
  • Citation-enforced answers grounded in retrieved documents, audited per tenant
  • Admin console for providers, models, users, usage analytics, retrieval evaluation, and release-readiness gates

No performance metrics have been invented here — measurable numbers will be added once live production usage produces them.
